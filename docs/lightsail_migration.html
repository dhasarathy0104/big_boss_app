Screenshots never accumulate past a rolling 24 hours, so that ~2.4 GB figure is close to a ceiling, not a number that grows month over month. The one table that does grow indefinitely is the activity log (timestamps and app/site names, no images) — kept for historical timelines and productivity history. It's text, not images, so its growth is on the order of tens of MB per employee per month, not a real storage concern at this scale for years.

04 Does it hold at 300?

CheckStatus
Live-status dashboard query cost✓ fixed — rewritten to a small, fixed number of queries per request regardless of team size
Backend CPU/memory for the API workload✓ light — mostly small JSON in/out; a modest instance handles this comfortably
Database write load (activity + screenshots)watch — the real load-bearing part; sized for in the plan below
300 concurrent screenshot uploads✓ fine — Node handles concurrent connections asynchronously; uploads land over ~5 minutes, not all at once
What "Live-status query cost" means

The Live tab shows every employee's status (Active/Idle/Offline) and refreshes automatically every 15 seconds. The code used to look up each employee's status one at a time — fine for 10 people, but at 300 employees that's 300 separate database lookups, repeated every 15 seconds, for every manager or the super admin with that tab open. That would have made the dashboard visibly slower as the team grew. It's been rewritten to fetch everyone's status in one batch — 2–3 lookups total, whether the team is 10 people or 3,000 — so this is already resolved, not something the Lightsail move needs to fix.

What "database write load — watch" means

There's a difference between the database being asked a question (reading — like the Live tab above) and being told to save something (writing). Every 30 seconds, each employee's agent sends new activity data; every 5 minutes, it sends a screenshot. That's a steady stream of save operations, all day, from every connected employee at once — and writing to disk is inherently more work for a database than reading from it. This row is marked "watch" rather than "fixed" because, unlike the query-cost issue, it hasn't been tested under real 300-employee load yet — it's the reason the database plan below has some headroom built in rather than being the cheapest option available, not a sign something is currently broken.

07 What actually changes vs. today

Render — today

  • Free tier: $0/month
  • Spins down after ~15 min idle — first request after a quiet spell takes ~50s to wake up
  • Free database has a fixed lifetime and needs renewal before it lapses
  • Deploys automatically on every push

Lightsail — proposed

  • ~$25/month, always on
  • No cold start — instant response any time of day
  • Database on a paid, stable plan — no expiry to track
  • Deploys are a manual or scripted step, not automatic on push (set up separately)
